# Архитектура Nixie Clock (ESP32 + ИН-12)

> Даты принятия решений: июнь 2026

---

## 1. Аппаратная часть

### Элементная база

| Компонент | Назначение |
|-----------|------------|
| ESP32 DevKit v1 (30 pin) | Главный контроллер |
| DS3231 RTC-модуль | Аппаратные часы реального времени (I²C) |
| 74HC595 (x2 или x3) | Сдвиговые регистры для преобразования последовательного интерфейса в параллельный |
| К155ИД1 (x2 или x3) | Высоковольтные дешифраторы BCD → 1 из 10 (для управления ИН-12) |
| ИН-12 (x4 или x6) | Газоразрядные индикаторные лампы |

### Подключение

```
ESP32 GPIO
├── 13 (DATA)   → 74HC595 #1 DS
├── 4  (PWM)     → High-voltage module EN (brightness control)
├── 14 (CLOCK)  → 74HC595 #1 SH_CP  (общий для всех)
├── 15 (LATCH)  → 74HC595 #1 ST_CP  (общий для всех)
├── 21 (SDA)    → DS3231 SDA
├── 22 (SCL)    → DS3231 SCL
```

**74HC595 daisy-chain**: выход Q7' каждого предыдущего регистра соединён со входом DS следующего.
Один 74HC595 = 8 бит = 2 лампы (по 4 бита BCD на каждую К155ИД1).

### Конфигурация ламп

В `src/config.h` константа `LAMP_COUNT`:

| Значение | Ламп | Формат |
|----------|------|--------|
| `LAMPS_4` (4) | 4 | `ЧЧ:ММ` — 2 регистра |
| `LAMPS_6` (6) | 6 | `ЧЧ:ММ:СС` — 3 регистра |

## 2. Софтверный стек (библиотеки)

| Задача | Решение | Обоснование |
|--------|---------|-------------|
| Работа с I²C / RTC | `RTClib` от Adafruit (v2.1+) | Проверенная, стабильная работа с DS3231 |
| WiFi | `WiFi.h` (штатная в ESP32 Arduino Core) | Стандарт, без зависимостей |
| NTP | `configTime()` + `::time()` из `time.h` | Встроенная SNTP-поддержка ESP32 SDK |
| BLE | `NimBLE-Arduino` от h2zero (v1.4+) | Apache NimBLE вместо Bluedroid; ~200 KB вместо ~1.1 MB |
| JSON | `ArduinoJson` от Benoit Blanchon (v7+) | Лёгкая, эффективная, стандарт де-факто |
| Сдвиговые регистры | Собственный класс `ShiftRegister` | Минималистичная bit-bang реализация |
| PWM (яркость) | `PwmManager` (LEDC ESP32 Core) | ШИМ 2 кГц, 13 бит, GPIO 4 — управление яркостью ламп (0–100 %) |

## 4. Workflow времени

```
                    ┌───────────────────┐
                    │   ESP32 Boot      │
                    └────────┬──────────┘
                             │
              ┌──────────────▼──────────────┐
              │  Чтение RTC (DS3231)        │
              │  Если lostPower → флаг       │
              └──────────────┬──────────────┘
                             │
              ┌──────────────▼──────────────┐
              │  WiFi: автоподключение      │
              │  (если сохранены креды)     │
              └──────────────┬──────────────┘
                             │
              ┌──────────────▼──────────────┐
              │  NTP: SNTP sync (до 3      │
              │  попыток по 20 с)           │
              │  При успехе → обновить RTC  │
              └──────────────┬──────────────┘
                             │
              ┌──────────────▼──────────────┐
              │  Основной цикл:             │
              │  каждые 100 мс →            │
              │  getCurrentUTC():           │
              │    1. NTP system time (если synced)
              │    2. RTC time (если доступен)
              │    3. system time fallback
              │  → применить часовой пояс   │
              │  → отобразить на лампах     │
              │                             │
              │  Каждые 24 ч → новый NTP    │
              │  sync (автоматически)       │
              └─────────────────────────────┘
```

**Важно**: RTC — основной поставщик времени. NTP служит только для периодической
коррекции (1 раз в сутки). Это гарантирует корректное время даже без WiFi.

## 5. BLE-протокол

### Параметры подключения

- **Имя устройства**: "Nixie Clock"
- **Тип**: BLE GATT Server (не Classic Bluetooth)
- **Сервис**: `e20a39f4-73f5-4bc4-a12f-17d1ad07a961`
- **TX характеристика** (ESP32 → телефон): Notify, UUID `e20a39f5-...`
- **RX характеристика** (телефон → ESP32): Write, UUID `e20a39f6-...`

### Формат команд (JSON)

Запрос:
```json
{"cmd": "<command>",  "param1": "value1",  ...}
```

Ответ (синхронный, через Notify):
```json
{"event": "response",  "cmd": "<command>",  "status": "ok",  ...}
```

Асинхронные события (без команды):
```json
{"event": "wifi",  "status": "connected",  "ip": "192.168.1.100"}
{"event": "wifi",  "status": "disconnected"}
{"event": "ntp",   "status": "synced"}
{"event": "ntp",   "status": "failed",  "message": "..."}
```

### Команды

| Команда | Параметры | Описание |
|---------|-----------|----------|
| `set_wifi` | `ssid` (string), `password` (string) | Сохранить в NVS и подключиться к WiFi |
| `forget_wifi` | — | Стереть креды WiFi из NVS |
| `set_time` | `timestamp` (int, Unix epoch) | Установить время вручную (RTC + system) |
| `set_timezone` | `offset` (int, -12..+14) | Часовой пояс относительно UTC |
| `set_format` | `value` ("12h" \| "24h") | Формат отображения на лампах |
| `get_status` | — | Полный статус: WiFi, NTP, RTC, TZ, время, яркость |
| `get_version` | — | Версия прошивки, количество ламп |
| `ota` | `url` (string) | OTA-обновление: скачать прошивку по URL и перезагрузиться |
| `list_commands` | — | Список всех зарегистрированных команд |
| `reboot` | — | Перезагрузка ESP32 |
| `set_brightness` | `value` (int, 0–100) | Яркость ламп (ШИМ 2 кГц, GPIO 4) |

### OTA-события

Во время OTA-обновления ESP32 отправляет асинхронные события:

```json
{"event":"ota","status":"started"}
{"event":"ota","status":"progress","percent":35}
{"event":"ota","status":"success"}
{"event":"ota","status":"failed","message":"HTTP 404"}
```

После `success` устройство автоматически перезагружается в новую прошивку.

## 6. Система команд (registry pattern)

`CommandHandler` содержит `std::map<String, Handler>`. Каждая команда
регистрируется вызовом:

```cpp
g_cmdHandler.addCommand("set_timezone", [](const JsonObject &cmd,
                                            JsonObject &resp) {
    // ... валидация, выполнение ...
});
```

**Для добавления новой команды** достаточно:
1. Написать handler с сигнатурой `(const JsonObject &cmd, JsonObject &resp)`
2. Зарегистрировать его в `registerCommands()` в main.cpp

Никаких других изменений в диспетчере не требуется.

## 8. Display logic

- **24-часовой** по умолчанию, переключается через `set_format`
- **Ведущий ноль не гасится** (всегда `00:00`..`23:59`)
- **Точки-разделители**: не используются (в данной версии)
- При отсутствии валидного времени (не инициализирован RTC, нет NTP):
  через 3 секунды лампы гасятся (`blank()`) до появления времени
- Частота обновления дисплея: 10 Гц (100 мс)

## 9. Обработка ошибок WiFi/NTP

### WiFi
- Non-blocking connect с таймаутом 15 с
- Авто-реконнект при разрыве (через `WiFi.setAutoReconnect(true)`)
- Если кредов нет — часы работают только от RTC, BLE всегда доступен

### NTP
- До 3 попыток синхронизации при старте (таймаут 20 с каждая)
- При неудаче: `_ntpGiveUp = true` до следующего переподключения WiFi
- Если NTP ранее синхронизировался (например, при daily sync):
  при неудаче просто пропускаем, keep `_ntpSynced = true`
- Daily sync: ровно 1 попытка, при неудаче — повтор через 24 ч
- При успешной синхронизации: RTC обновляется автоматически

## 10. Зависимости (PlatformIO)

```ini
[env:esp32dev]
platform = espressif32
board = esp32dev
framework = arduino
board_build.lto = true
lib_deps =
    adafruit/RTClib @ ^2.1
    bblanchon/ArduinoJson @ ^7.0
    h2zero/NimBLE-Arduino @ ^1.4
lib_ignore = ESP32 BLE Arduino   ; заменяем Bluedroid (~1.1 MB) на nimBLE (~200 KB)
```

BLEDevice, WiFi, Preferences входят в состав ESP32 Arduino Core.

Используется стандартная OTA-совместимая таблица разделов
(два слота по 1256 KB для обновлений по воздуху).
